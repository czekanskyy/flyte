# FLY-014 – Better Auth: email/password, passkeys, Google, magic link

## Session 1 · 2026-08-28 · completed

**State:** done. Landed on `main` as squash #10 (`166f26f`).

**Done:**

- Self-hosted Better Auth 1.7.2 on the FLY-012 Drizzle tables. Catch-all
  `GET`/`POST` `/api/auth/[...all]`.
- Email/password always on. Passwords hashed with Argon2id via catalog `argon2`
  0.45.1 (Better Auth 1.7.2's own default is scrypt; ADR 0005 requires Argon2id,
  so hashing is custom).
- Sessions are database-backed (`better-auth.session_token`, HttpOnly, 7 days).
  No JWT-as-session.
- Passkeys always on (`@better-auth/passkey`). Register from `/login` when
  already signed in. Sign-in button on the same page. CI cannot exercise
  WebAuthn; the implementer should confirm on Windows Hello.
- Google button only when `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are both
  set. Observed locally: button **visible** (owner env has both). Not called
  from CI.
- Magic-link form only when SMTP host/user/password/from are all set. Observed
  locally: form **hidden**. `sendMagicLink` uses a small SMTP client (implicit
  TLS on 465, STARTTLS otherwise). Magic-link URLs are not logged.
- `(app)` is gated: `proxy.ts` redirects when the session cookie is missing;
  `(app)/layout.tsx` checks `auth.api.getSession`. Unauthenticated `/pl` goes to
  `/pl/login`. `/api/health` and `/api/auth/*` stay public (matcher).
- Copy in `messages/pl/auth.json` and `messages/en/auth.json`. No U+2014.
- Unit tests: feature flags, Argon2id prefix, locale path helpers. Password
  round-trip test exercises the native argon2 build.
- Migration `0001_fly014_account_issuer.sql`: Better Auth 1.7.2 requires
  `account.issuer` with a unique `(issuer, account_id)` index. Applied to Neon
  **dev**.

**Exercised locally:**

- `/pl` with session cookie → 200 home page.

- Passkey registration/sign-in: **not** exercised (no WebAuthn ceremony in this

- Google OAuth: button rendered, not clicked.
- Magic link: not configured, form hidden.

**Not done:** first-run acknowledgement (FLY-019), theme (FLY-015), PWA (FLY-016).

**Decisions made, do not re-litigate:**

- `getAuth()` is lazy so `next build` in CI (no `DATABASE_URL`) still compiles.
  `next.config.ts` calls `loadRepoEnv()` so the repo-root `.env.local` is visible
  to Next, which only auto-loads `apps/web/.env*`.
- Drizzle adapter `transaction: false` because FLY-012 uses `neon-http`.
- Catalog gained `@better-auth/drizzle-adapter` and `@better-auth/passkey` at
  1.7.2, the same release as `better-auth`. These are the official split packages
  of ADR 0005, not a new auth decision. `argon2` is in `allowBuilds`.
- `apps/web` tsconfig sets `declaration: false` so Better Auth's Zod types do
  not trip TS2883.
- SMTP is implemented with `node:tls` / `node:net` rather than adding nodemailer
  (new dependency would need an ADR).

**Watch out:**

- Next's bundler passes `import.meta.url` as a URL object. `load-env.ts` must
  `String(import.meta.url)` before `fileURLToPath`. Without that, `next build`
  dies while collecting `/[locale]/login`.
- Better Auth 1.7.2 account identity is `(issuer, accountId)`, not `accountId`
  alone. Credential issuer is `local:credential`.
- `proxy.ts` is cookie-only (Better Auth's recommended optimistic check). Real
  validation is in `(app)/layout.tsx`.
- Extra paths outside `owns_paths` were required wiring: `apps/web/package.json`,
  `pnpm-workspace.yaml`, `apps/web/next.config.ts`, `apps/web/src/i18n/request.ts`,
  `apps/web/src/app/[locale]/(app)/layout.tsx`, `apps/web/src/components/app-chrome.tsx`,
  `packages/db/src/load-env.ts`, `apps/web/tsconfig.json`.
