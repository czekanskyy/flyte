# FLY-011 – Shared config, Vitest, CI

## Session 1 · 2026-08-28 · completed

**State:** in-review. Branch `feat/FLY-011-shared-config`.

**Done:**

- `packages/config` exports tsconfig (strict + `noUncheckedIndexedAccess`), ESLint flat
  config, Prettier, and a shared Vitest config.
- `eslint-plugin-boundaries` treats each workspace package as one element. Allowed edges:
  aviation-data → aviation; ui → aviation, aviation-data; web → all of those plus db and
  config. aviation and db have no allowed workspace edges.
- `no-restricted-imports` on `packages/aviation/src/**` bans react, next, `@flyte/{ui,db,
  aviation-data,config}`, and Node I/O modules. A source file importing `react` fails lint.
- Prettier formats application code. Markdown/docs are ignored (prose gate owns those).
- Vitest workspace. `@flyte/aviation` has a smoke test. Other packages pass with
  `passWithNoTests`.
- `.github/workflows/ci.yml` installs pnpm 11.24.0 and Node 24, then `pnpm verify`.
- Catalog additions (npm view 2026-08-28): `@eslint/js` 10.0.1, `eslint-plugin-react-hooks`
  7.1.1, `eslint-config-prettier` 10.1.8, `globals` 17.11.0.
- `pnpm verify` green locally. `tsc` is 6.0.3.

**Not done:** Next.js app (FLY-013). Real `eslint-plugin-react` (peer range stops at ESLint 9).

**Decisions made, do not re-litigate:**

- `eslint-plugin-react` is **not** in the catalog. 7.37.5 peers `eslint` `^9.7` and
  `strict-peer-dependencies` would fail the install. Recorded in ADR 0001. FLY-013 can add
  `eslint-config-next` instead.
- Type-aware `parserOptions.projectService` is off. It fought vitest.config.ts files
  (`allowDefaultProject` rejects `**` globs). `tsc --noEmit` remains the type gate.
- ESLint runs from the repo root (`pnpm lint`), not via turbo per package, so boundary
  `files` patterns stay relative to the monorepo root.

**Watch out:**

- Element descriptors are folder-level (`pattern: "packages/aviation"`), not `mode: "file"`.
  File mode made every file its own element and then flagged intra-package imports.
- Root `package.json` has `"type": "module"` so `eslint.config.js` is ESM without a warning.
- PR #3 merged into `docs/phase-1-foundation`, not `main`. #4 cherry-picked it onto `main`.
  Later stacked PRs must target `main`.
