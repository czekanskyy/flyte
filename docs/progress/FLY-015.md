# FLY-015 – UI kit, glassmorphism, theme, night mode

## Session 1 · 2026-08-29 · completed

**State:** in-review. Branch `feat/FLY-015-ui-theme-night`, stacked on FLY-014
(`feat/FLY-014-better-auth`). Merge PR #10 first, then this PR onto `main`.

**Done:**

- Owner decision recorded as [ADR 0014](../adr/0014-glassmorphism.md): glassmorphism is the
  visual language for the whole application (Apple-like, large radius, translucent chrome).
  Night is red glass, more opaque. Sunlight: fills stay higher than marketing glass.
  `prefers-reduced-transparency` disables blur.
- [ADR 0013](../adr/0013-shadcn-ui.md): copy-in kit in `packages/ui`. CLI zinc theme is not
  the product. No new catalog packages this PR (cva / tailwind-merge / Radix wait until a
  component needs them).
- `@flyte/ui` exports `Button`, `Input`, `Label`, `ThemeProvider`, `ThemeSwitch`.
- Tokens in `packages/ui/src/styles.css`. Web imports `@flyte/ui/styles.css`.
- Themes `light` / `dark` / `night` via `data-theme` on `<html>`. Default `dark`.
  Persistence `localStorage` key `flyte-theme`. Inline script avoids a white flash.
- Theme switch in the shared chrome (login and home). Copy in `messages/{pl,en}/theme.json`.
- Login, home and top bar use the glass material. Auth forms use `@flyte/ui` controls.
- Unit test: `applyTheme("night")` writes `data-theme`. No jsdom in the catalog, so no RTL
  click test of `ThemeSwitch` this PR.
- `pnpm verify` green (this session).
- AGENTS.md and CONTRIBUTING.md point at ADR 0014 so later agents do not undo it.

**Not done:** Tailwind 4 utilities inside components; shadcn CLI add of further primitives;
accent/transparency/radius sliders (Phase 8 binds the tokens). Print templates stay
unglassed.

**Decisions made, do not re-litigate:**

- Default theme is dark so a cockpit does not flash white before storage is read.
- Glass fill is deliberately denser than Dribbble glassmorphism. Opacity is a token for
  Phase 8, not a second design.
- Theme labels are passed into `ThemeSwitch` so `@flyte/ui` does not import next-intl.

**Watch out:**

- `next.config.ts` must `transpilePackages: ["@flyte/ui"]`.
- Do not commit `apps/web/next-env.d.ts` if `next dev` injects `.next/types` imports.
- Extra paths outside the original owns_paths: `AGENTS.md`, `docs/CONTRIBUTING.md`,
  `(auth)` login forms, `app-chrome`, locale layout, `i18n/request.ts`. Required to apply
  the owner rule on every current screen.
