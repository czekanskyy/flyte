**Verify:** `pnpm verify` green (69 aviation tests, typecheck, lint, prose, web build).

**Decisions made, do not re-litigate:**

- Factors are the DOMAIN expressions (`1852 / 3600`, `1 / 3.6`, `0.3048 / 60`, `5 / 9`),
  never six-digit printouts. Inverse is divide by the same factor.
- No fuel density helper. Volume stays volume.
- TypeScript does **not** make `metres(1) + feet(1)` a type error. Branded numbers are
  still `number` under `+`; the result is unbranded `number`. ADR 0008 / AGENTS.md
  illustrate a compile error on `+` itself. That illustration is false in tsc 6.0.3.
  The real gate is assignment. Do not switch to object wrappers: ADR 0008 says the
  brand is erased and the numbers stay numbers.
- Property tests skip `|x| < 1e-6` (IEEE underflow under a linear factor) and, for
  offset conversions (°C↔K, °F↔°C), `|x| < 0.01`. Those floors are test bounds, not
  aviation constants. Relative 1e-9 cannot hold for `|t| << ULP(273.15)`.
- `pnpm-lock.yaml` added to this task's `owns_paths` because fast-check (already in the
  catalog, ADR 0001) had to be declared on `@flyte/aviation`.

**Rejected:**

- Adjusting a golden vector when a property test failed. The failures were denormals
  (`5e-324`) and offset cancellation around 1e-6 °C, not wrong factors. Vectors
  untouched.
- Replacing `1852 / 3600` with the IEEE literal `0.5144444444444445` in source. The
  ratio is the spec; the JSON expect is that IEEE value so `tolerance: 0` can hold.

**Watch out:**

- `packages/aviation/tsconfig.json` includes `src` and `test` so the JSON import type-
  checks. Putting `rootDir: "src"` back will fail `tsc` on `test/vectors/units.json`.
- fast-check `fc.double({ min: -1000, max: 60000 })` includes subnormals near zero.
  Filter them; do not loosen a golden vector.
- Do not "fix" mixed `+` by changing the brand to an object. Next agent will see the
  AGENTS.md snippet, try `@ts-expect-error` on `metres(1) + feet(1)`, and get an unused
  directive because the expression type-checks.
