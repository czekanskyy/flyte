# FLY-012 – packages/db: Drizzle, Neon, PostGIS, auth schema

## Session 1 · 2026-08-28 · completed

**State:** in-review. Branch `feat/FLY-012-db-drizzle-neon`, stacked on the FLY-013
promote commit (PR #6 merged into `feat/FLY-011-shared-config`, not `main`).

**Done:**

- `@flyte/db` talks to Neon via `drizzle-orm/neon-http` and `@neondatabase/serverless`.
- Schema in `src/schema/auth.ts`: Better Auth `user`, `session`, `account`,
  `verification`, plus `passkey` for the passkey plugin. No extra application columns.
- Migration `0000_fly012_postgis_and_auth.sql` starts with
  `CREATE EXTENSION IF NOT EXISTS postgis;` then the tables.
- `pnpm db:generate`, `pnpm db:migrate`, `pnpm db:check:postgis` at the repo root.
- Migrate applied to the Neon **dev** branch. Second run is a no-op.
- `pnpm db:check:postgis` printed `PostGIS 3.6` (no connection string).
- Unit test of table names does not need the network.
- `pnpm verify` green.

**Not done:** Better Auth config, API routes, UI (FLY-014).

**Decisions made, do not re-litigate:**

- Env files are parsed by `loadRepoEnv()` in-process. No `dotenv` package (not in the
  catalog).
- Schema is hand-written to match Better Auth 1.7.2 docs, then `drizzle-kit generate`.
  The generated filename was renamed to `NNNN_fly012_*` and the journal tag updated.
- `esbuild` is in `allowBuilds` so drizzle-kit's bundled esbuild may postinstall.

**Watch out:**

- `packages/db` tsconfig sets `"types": ["node"]`. Without it, `tsc` cannot see
  `node:fs` / `process` even with `@types/node` installed.
- FLY-013 is still not on `main`. This branch includes the cherry-pick. Merge the
  promote PR first, then this one.
- Never log `DATABASE_URL`.

**Next concrete step:** FLY-014 Better Auth, after this lands.
